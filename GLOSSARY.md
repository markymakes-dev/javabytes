# JavaBytes

The language of the JavaBytes conversion pipeline. JavaBytes converts JavaScript/TypeScript applications into working Java applications: it parses the source app's data layer, proposes a normalized database, generates a Spring Boot backend, and renders the UI according to a chosen UI strategy.

## Conversion

**Source app**:
The JavaScript/TypeScript application being converted to Java.
_Avoid_: input app, original project

**Target app**:
The Java application produced by a conversion.

**UI strategy**:
The per-conversion choice of what renders the interface: keep the original frontend (default), rebuild it in JavaFX (desktop), or rebuild it in Vaadin (browser, all-Java). `auto` lets the server pick and state why. JavaFX is a desktop UI, not a web technology.
_Avoid_: frontend strategy (implies web-only)

**Working app**:
The definition of done for a conversion: the target app compiles AND starts.
_Avoid_: "done generating"

## Schema facts

**Entity**:
A data declaration in the source app — a mongoose or prisma model, a sequelize model, a SQL `CREATE TABLE`, a JSON store record shape. Parsing produces exactly one Table per Entity.
_Avoid_: model (overloaded — also names the mongoose/prisma declaration itself)

**Field**:
A single declared attribute of an Entity, on the source side. Parses into exactly one Column.

**Table**:
One relational table in the schema model; the parse target of an Entity.
_Avoid_: collection, entity (after parsing)

**Column**:
One column of a Table: a logical type, the raw source/SQL type, and the nullability, default, uniqueness, and length facts known about it.

**Relation**:
A foreign-key relationship between two Tables: target table, joining columns, delete/update rules.

**Schema Model**:
The shared in-memory representation of a schema — Tables, Columns, Relations, Indexes — exchanged by all pipeline stages.
_Avoid_: "the model"

## Provenance & honesty

**Provenance**:
The origin class of any schema fact. Every schema fact in a report carries its provenance.

**Discovered**:
A schema fact read from a live database's schema catalog.

**Parsed**:
A schema fact extracted from source code.

**Proposed**:
A schema fact generated by JavaBytes, such as normalized DDL. Always carries "verify before executing".

**Confidence**:
Per-fact, three levels only: high (explicitly declared in the source), medium (inferred from usage patterns), low (heuristic guess). Never numeric.

**Honest subset**:
The portion of the source app JavaBytes translates — only constructs it can prove compile. Everything else becomes Manual work.

**Manual work**:
Anything the pipeline cannot prove correct, reported as a list for human follow-up rather than guessed at.
_Avoid_: TODO comments in generated code
